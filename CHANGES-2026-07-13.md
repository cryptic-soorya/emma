## Bug Fix (pre-existing)

`save-cat-result` wrote the mock session with `{ ...session, sessionId: undefined }`. The Firestore client SDK **throws** on `undefined` field values (`firebase.ts` does not set `ignoreUndefinedProperties`), which would have made every mock save fail at runtime. Fixed by deleting the key instead of setting it undefined, and stripping undefined optional fields from attempts as belt-and-braces. Same care taken in the new revision-queue writes (`lastErrorType` only written when known).

## New Features — Rationale

1. **Revision Queue (spaced repetition)** — CAT prep's biggest silent failure is re-making the same mistakes. Every wrong attempt is already recorded, so queueing them for re-test at expanding intervals is close to free and directly converts mock data into retention. Firestore doc: `revisionQueues/{studentId}` (single doc, array of items — fine at CAT scale of ~30–60 wrong questions per student).
2. **Weak Chapter Drill** — skip recommendations diagnose; drill mode treats. A student either recovers a chapter (and keeps attempting it) or confirms it belongs on the skip list. Reuses `CATQuestionCard` and the existing `catQuestions` structured queries — the "RAG-lite" pattern CLAUDE.md Phase 5 describes, applied to practice.
3. **Study Streak** — one small field on `studentProfiles`, updated on mock submit (server) and drill/revision completion (client, best-effort). Displayed on `/cat`. Cheap, and consistency is the highest-leverage behavior for a CAT aspirant. Institute dashboards can later surface "streak broken" alerts with zero schema work.

Considered but not built: mock calendar/reminders (needs notification infra), WhatsApp/email digest (needs a sender service), peer percentile comparison (needs enough students per institute to be meaningful — revisit after pilot data exists).
